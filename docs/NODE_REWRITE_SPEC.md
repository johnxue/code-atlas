## 3. 引擎层语义（engine.mjs）——与 run_ast_grep 契约对齐

### 3.1 扫描执行
Bash 版每条规则 = 一次 `ast-grep run --lang L (--pattern P | --kind K) --json DIR`。
Node 版改为：每个语言对该语言全部文件**解析一次缓存 AST**（同文件同语言不重复 parse），然后 `root.findAll({rule:{pattern}})` 或 `{rule:{kind}}`。
⚠️ 缓存是性能优化，但必须保证与"逐规则独立调用 CLI"结果完全一致：pattern/kind 匹配不得受缓存影响（findAll 是纯查询，天然满足）。

### 3.2 错误语义（必须复刻）
- 该语言在目录下**无文件** → 合法空结果，静默跳过（Bash 版 rc=1 语义）。
- pattern 含 ERROR 节点 / 非法 → 记录诊断 `⚠️ [lang/subject] <msg>`，该规则返回空，**不阻断**整图。
- 文件解析失败 → 记诊断，跳过该文件继续。
- 未知语言名 → 记诊断并跳过（不阻断）。
- 诊断全部进 warnings 列表，最终写地图 ⚠️ 区页脚 + stderr 回显（格式见 §5.8）。

### 3.3 napi 与 CLI 的输出差异点（翻译时注意）
- CLI JSON 的 `range.start.line` 是 0 基，所有行号输出 `+1`——napi 的 `range().start.line` 同为 0 基，规则一致。
- `metaVariables.single.NAME.text` → napi `match.getMatch('NAME')?.text()`。
- 节点 `text`、`file`（相对路径换算见 §5.1）语义不变。
- **验证要求**：对 wisdom_app 的 `lib/features/player` 子集，kind 计数须等于基线：class_declaration 29 / enum_declaration 1 / top_level_variable_declaration 12 / method_declaration 110 / library_import 60。

## 5. 输出契约（逐字节规格）

### 5.1 行格式
- 符号行：`📁 <repo相对路径> [L<行号>] <标签> <符号名>`
- 路由行：`📁 <file> [L<n>] <prefix> <PATH> → <HANDLER>`
- 导入行（中间态）：`📁 <file> [L<n>] import <module>`
- 相对路径换算：文件绝对路径若以 `TARGET_DIR_ABS + '/'` 开头则截去该前缀，否则保留原样（对应 jq 的 `if startswith($base)`）。路径分隔一律正斜杠。

### 5.2 Header（write_freshness_header）
依次输出（每行 `# ` 前缀）：
```
# Architecture Map: <name>
# Source Path: <TARGET_DIR_ABS>            # merge 模式: (merged — 见下方逐模块 Merged Source 行)
# Generated by: <见下>
# <extra 行，仅 merge 模式>                 # 每行 '# Merged ...' 
# Source Commit: <sha|unavailable>          # merge 模式: unavailable (merged)
# Worktree: <clean|dirty|unavailable>       # merge 模式: unavailable (merged)
# Scanner Version: <见下>
# ast-grep Version: <见下>
# Languages: <逗号连接的启用语言列表，顺序固定为 typescript,javascript,tsx,python,go,dart,kotlin,java,swift,c,cpp 的启用子集>
```
之后跟一个空行。HEADER_LINES = `#` 行数 + 1。
**有意差异许可**：`Generated by` 改为 `# Generated by: ast-grep napi engine (scan_repo_map.mjs v2.0.0)`；`Scanner Version: 2.0.0`；`ast-grep Version` 行改为 napi 版本号（`@ast-grep/napi` 包版本）。golden 对比时测试用与 Bash 版相同的 normalize（删除这三行类易变行）。

### 5.3 排序
全部排序 = **LC_ALL=C 字节序**。JS 实现：对键用 `<`/`>` 按 UTF-8 字节比较（可 `Buffer.compare(Buffer.from(k,'utf8'))`；对 BMP 内字符默认字符串比较等价）。数值行号列按数值升序。所有 `sort -u` = 排序后去重（整行为键）。

### 5.4 符号区组装（assemble_symbols，主流程与 merge 共用）
1. 行 → 4 列：`路径 \t 行号 \t 标签 \t 名字`（正则：`^(.*) \[L(\d+)\] (\S+) (.*)$`）。
2. `sort -t\t -k1,1 -k2,2n`（路径字节序 → 行号数值）。
3. 同 `(路径,行号,名字)` 去重：保留**标签优先级最高**的行。优先级列表（靠前优先，完整照抄）：
   `nest-controller nest-service nest-module typeorm-entity room-entity room-dao hilt-module composable swiftui-view final-class data-class sealed-class sealed-interface abstract-class object-singleton dataclass pydantic-model orm-model django-model typed-dict tortoise-model mixin extension type-alias cpp-namespace namespace zod-schema valibot-schema typebox-schema zustand-store pinia-store redux-slice redux-thunk trpc-router hono-app express-router custom-hook react-context forward-ref-component memo-component default-component react-component const-func async-const-func vue-component enum interface class`
   不在列表的标签优先级 -1（最低）。**实现注意**：Bash awk 是「后出现的更高优先级行替换已缓存行」且按排序顺序扫描——同 key 时若优先级**严格大于**才替换，等优先级保留先出现者。
4. 还原行格式；`--max-lines N` 时截前 N 行。

### 5.5 🌐 导入图谱区
`sort -u` → exclude 过滤 → 转 3 列（路径/行号/模块）→ `sort -k1,1 -k2,2n` → 按路径聚合：`📁 <file> [L<首个行号>] imports(<次数>): <模块1, 模块2, ...>`（同文件模块按行号序拼接，不去重——同一模块被 import 两次会出现两次，照原样）。

### 5.6 🚪 文件符号清单区（仅 CROSSLAYER=1）
符号区行 → 取路径与名字的**最后一个空格分段**为符号名 → 跳过 `anonymous`/`?` → 按路径聚合，同文件内同名去重 → `🚪 <file> exports(<去重后总数>): <名1, 名2, ...>`，超 25 个截断为前 25 + ` …+<剩余数>`。排序：路径字节序。

### 5.7 🔗 反向引用区
导入行 `sort -u` → exclude → 3 列 → `sort -k3,3 -k1,1`（模块序→文件序）→ 按模块聚合（同模块同文件去重，importers 计去重后文件数，名单最多 10 个 + ` …+N`）→ 再对聚合结果整行 `sort` → 外部依赖折叠（§6.3）→ 格式化：折叠的 `🔗 <module> (<N> importers, external)`，未折叠 `🔗 <module> (<N> importers): <files...>`。

### 5.8 📡 API 区与 ⚠️ 诊断区
- API 区：`sort -u(routes)` 与 `sort -u(urls)` 拼接 → exclude → assemble_api：转 4 列（标签须匹配 `api-\S+`）→ `sort -k1,1 -k2,2n` → 同 `(路径,行号,名字)` 去重时 `api-route` 优先于其他 → 还原。
- 诊断区：`## ⚠️ 诊断（本次扫描中的 ast-grep 问题）` + warnings 原文（格式 `⚠️ [lang/subject] msg`，subject 内换行替换为空格）。merge 模式标题为 `## ⚠️ 诊断（原各模块扫描中的 ast-grep 问题）` 且 `sort -u`。
- 区标题（逐字节照抄 Bash 版 printf 字符串，含前后空行结构）：`## 🌐 导入图谱（跨层链路：文件 → 依赖模块）`、`## 🚪 文件符号清单（文件内符号全集，跨层链路终点）`、`## 🔗 反向引用：被导入模块 ← 引用文件（改动影响面）`、`## 📡 API 路径（api-route 路由定义 / api-call 调用点，跨端链路线索）`。
- 空区分片不输出该标题（Bash 版 `[[ -s ... ]]` 守卫）。

### 5.9 控制台输出
- 扫描：`🔍 Scanning [<name>] in <abs>...`；完成：`✅ Generated [<name>] map -> <out> (<N> symbols)`（N = 输出文件总行数 − HEADER_LINES）。
- merge 完成：`✅ Merged [<name>] -> <out> (<N> symbols)`。
- 有警告时 stderr：`⚠️ 发现 <n> 条警告（详见地图页脚）：` + 警告全文。
- 错误一律 stderr + 非零退出：`❌ Unknown option: ...`（打印 help，exit 1）、`❌ Error: Target directory does not exist: ...`、`❌ --merge 需要至少一个输入地图`、`❌ 输入地图不存在: ...`、Source Path 不一致警告 `⚠️ 输入地图 Source Path 不一致（...）：...`。

## 6. 文本处理等价物（textproc.mjs / normalize.mjs）——逐个对照翻译

### 6.1 jq 程序 → JS 函数（语义逐一对应，正则在 JS 中等价改写）
- `import_raw.jq`：取 metavar 文本，空则丢。
- `import_as.jq`：metavar 文本去 ` as .*$` 后缀，压缩空白，trim。
- `import_kind_dart.jq`：节点文本取第一个引号对之间的内容。
- `import_kind_go.jq`：节点文本去 `"` 后按空格 split 取最后一段。
- `import_kind_js.jq`：去 `^import `；含 ` from ` 则取 ` from ` 之后；去行尾 `;`+换行；去首尾引号。
- `urls.jq`：调用节点文本 → 去 `^[^(\n]*\(` → trim 头 → 去字符串前缀 `[bfruBFUR]*` → 首字符须为引号 → 取引号包围内容；长度 >1 且（以 `/` 开头 或 含 `://`）才输出。
- `classlike.jq`（dart/swift/java 三语言关键字正则表）与行号修正（节点起始行 + 关键字前换行数）、标签判定树、Java 注解前缀 room-entity/room-dao 判定（注解 = 节点文本中关键字匹配起点之前的部分）——**逐分支对照 lib.sh:105-144 翻译**。
- `dart_topvar.jq`：名字 = `=` 或 `;` 前段压缩空白后最后一个 token（尾字符须 `[A-Za-z_0-9]` 否则 `?`）；文本含 `Provider` → 标签 `provider` 否则 `top-var`。
- `extract_kinds` 的 symname：`split("(")[0]`→`split("=>")[0]`→`split("{")[0]`→去`;`→压缩空白→trim→最后一段；auto 模式标签树照 lib.sh:408-415。

### 6.2 normalize_imports.pl → normalize.mjs
逐分支对照 lib.sh:157-226：相对路径 `./ ../`、同目录裸文件名导入（dart/ts/tsx/js/jsx 扩展名形态）、Python 相对（前导点数）与绝对点式导入、Dart `package:`（MAP_PKG 自身包 → `lib/<rest>`，不依赖文件存在；否则探测 `lib/`、`src/`）。canon() 路径段归一化、fexists 缓存、扩展名探测顺序（`.ts .tsx .js .jsx .mjs .dart .py`，然后 `/index.ts /index.tsx /index.js /index.jsx /__init__.py`）、降级保留原文——全部照原语义。MAP_PKG 从 `<dir>/pubspec.yaml` 或 `<dir>/../pubspec.yaml` 的 `name:` 行读取（去空格引号）。
触发条件：CROSSLAYER=1 且 imports 非空；失败时记诊断 `⚠️ [note/normalize] 导入归一化失败，保留原始 import 字符串`。

### 6.3 collapse_external.pl → normalize.mjs
仅折叠可证实外部依赖：`dart:*`、`package:非self`、在 `<base>`、`<base>/..`、`<base>/../..` 三处 `node_modules/<包名>` 存在的 JS 裸包名（含 `@scope/name` 形态）。其余原样保留。对照 lib.sh:230-249。

### 6.4 extract_dart_api_lines（Dart api-call 行级启发式）
对目录下全部 `.dart`（排除 `*/.*` 与 DEFAULT_EXCLUDES）逐文件正则扫描：
`/(?:\.(?:get|post|put|delete|patch|request|download)[^(\n]*|Uri\.parse[^(\n]*)\(\s*[frubFRUB]*(['"`])(.*?)\1/gs`，
URL 满足（`^/` 或含 `://`）且不含 `${` → 输出 `📁 <f> [L<ln>] api-call <url>`（行号 = 匹配起点前换行数+1）。文件读取失败记诊断 `⚠️ [dart/api-lines:<f>] Dart API 行级扫描失败: <msg>`（这是测试断言点）。

## 7. CLI 与 merge 模式

CLI 参数与 Bash 版完全一致：`-d/--dir`、`-o/--output`、`-n/--name`、`-x/--no-crosslayer`、`-e/--exclude`（可重复，值不得含 `|`）、`-m/--max-lines`、`--languages`、 `--merge <map...>`、`-v/--version`（输出 `scan_repo_map.mjs v2.0.0`）、`-h/--help`。
- `--languages` 校验：空值/空字段（首尾或连续逗号）/未知语言 → stderr 明确报错 + exit 1（空字段错误信息须含「空字段」二字，测试断言点）。合法值集合与默认顺序：`typescript,javascript,tsx,python,go,dart,kotlin,java,swift,c,cpp`。
- merge 模式：逐输入地图按 `## ` 区头分片（🌐/🚪/🔗/📡/⚠️ 各自归片，其余进符号片），`#` 注释行与空行跳过；逐模块从输入 header 读 `# Source Path:`/`# Source Commit:`/`# Worktree:`（缺 → `unavailable`），写 extra 头：`Merged from: <files...>`、`Combined by: scan_repo_map.mjs v2.0.0 (merge)`、逐模块 `# Merged Source Path: <src> (<file>)` 等三行；多输入 Source Path 不一致打 stderr 警告；输出组装：符号片走 assemble_symbols，🌐/🚪/🔗 片 `exclude + sort -u`，📡 片走 assemble_api，⚠️ 片 `sort -u`。
- `-e/--exclude`：行内容含任一子串即丢（输出级过滤，所有区统一走 exclude_rows）。
