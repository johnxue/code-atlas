## 1. 扫描器改动（~/development/scan_repo_map）

### 1.1 行格式
- 符号区**所有行**（含 extract_route 的 `http-get PATH → handler` 行，它们也写入符号区）：
  `📁 <file> [L<start>-L<end>] <label> <rest>`。**恒为区间形式**，单行符号写作 `[L3-L3]`，不做特例。
- 行号语义：start/end 均 1 基。end = napi `node.range().end.line + 1`（tree-sitter end 语义原样采用，不额外校正）。
- classlike 体系（dart/swift/java）start 行保持现有关键字修正逻辑（注解前偏移），end 取节点 end 行。
- import 行（🌐/🔗）、📡 api-call/api-route 行：**不改**，保持 `[L<n>]`。

### 1.2 波及点（逐一改）
- engine/extract：所有写符号区的路径把 end 行传入格式化（findAll 节点自带 range，零额外解析成本）。
- assemble.mjs 符号区解析正则：`\[L(\d+)\]` → `\[L(\d+)(?:-L(\d+))?\]`（容忍旧单行格式——merge 可能吃进 Bash v1.7.0 生成的旧地图，这是解析宽容不是兼容层）；排序键仍取 start 行数值；去重键 `(路径, start行, 名字)` 不变；输出保留原始区间文本。
- merge.mjs 同理解析宽容。
- assemble_api 不动（📡 区无区间）。
- Scanner Version → `2.1.0`（header `# Generated by:` 行同步）。CLI `-v` 输出同步。

### 1.3 测试更新（本仓）
- 现有 78 项断言中凡匹配行号的（如 `\[.*\]`）多数天然兼容；**新增**区间断言：对 fixture 中已知跨行符号（如 dartlib 的 `class Playable` 跨 5 行、`Future<void> fetchTracks` async 方法）断言其 `[Ls-Le]` 精确值，至少 3 条，覆盖：多行 class、单行 symbol（`[L3-L3]` 形式）、route 行区间。
- 新增「剥离对拍」：见 §6（替代原 golden 直 diff）。

## 2. build_review_packet.sh 改动（wisdom_app）

只改 🎯 区生成逻辑（现状：scripts/build_review_packet.sh `emit_symbol_entry`，文件级 ●/○ + hunk 头）：

1. 从地图**符号区**（不是 🚪 区）取该变更文件的逐符号行：`📁 <file> [Ls-Le] label name`（解析兼容 `[Ln]` 旧格式：视为 `[Ln-Ln]`）。
2. 从 `git diff` 解析该文件的 hunk 新区间（`@@ -a,b +c,d @@` → 新文件行区间 `[c, c+d-1]`，d=0 时为纯删除点）。
3. 逐符号标注：符号区间与任一 hunk 区间**相交** → `●`，否则 `○`。
4. 输出格式（🎯 区内，每变更文件一组）：
   ```
   ### <file>
   ● [L12-L30] method fetchTracks
   ○ [L45-L49] class AudioRepository
   hunk: @@ -10,6 +10,8 @@ …（保留现有 hunk 头供定位）
   ```
   文件未索引/新增 → 保持现有 `○ <file> (未索引)`；删除 → `○ <file> (deleted, 未索引)`。
5. 旧格式地图（Bash v1.7.0 产出，无区间）：文件内符号全部退化为单行区间参与求交（相交=该起始行落在 hunk 内），不报错、不特殊分支。
