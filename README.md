# Code Atlas (repo-map)

[中文](README.zh-CN.md) | [日本語](README.ja.md)

A Node.js + `@ast-grep/napi` rewrite of the Bash `scan_repo_map.sh` scanner. The repo root doubles
as the agent skill **repo-map** (see SKILL.md); the repo also contains the complete Node scanner
and the ast-grep dynamic language packages.

## Layout

```
bin/scan_repo_map.mjs   CLI entry (arg parsing/dispatch/validation), mirrors scan_repo_map.sh
src/
  engine.mjs            run_ast_grep equivalent: file discovery (gitignore) + per-language AST cache + findAll + error semantics
  extract.mjs           extract_symbols/route/kinds/kind_jq/import/import_kind/urls/dart_api_lines
  textproc.mjs          jq/perl equivalents: import cleanup, URL first-arg extraction, classlike labels, dart_topvar, symname
  normalize.mjs         import normalization + external-dependency collapsing
  assemble.mjs          sort/dedupe/trim + section assembly
  freshness.mjs         git metadata + header
  merge.mjs             --merge mode
  rules/*.mjs           per-language rule manifests (mechanically 1:1 with the Bash rules_*.sh)
test/
  scan_repo_map.test.mjs  84 assertions (port of the Bash test suite)
  rules_parity.test.mjs   mechanical cross-check of rule manifests against the Bash sources
  gitignore_parity.test.mjs  gitignore semantics parity vs the Bash implementation
  golden.sh               Node vs Bash strip-compare (normalized diff must be empty) + snapshot guard
  fixtures/               committed fixture repos
packages/lang-dart/     Dart dynamic language pack (@ast-grep/lang-* style)
  index.js              language registration entry (libraryPath / extensions / languageSymbol / expandoChar)
  type.d.ts             node-type declarations, generated by gen-types.js from src/node-types.json
  postinstall.js        falls back to a local build when no prebuild exists (@ast-grep/setup-lang)
  src/                  tree-sitter generate C output (grammar.json / parser.c / scanner.c / tree_sitter/)
  prebuilds/            prebuilt parser.so (prebuild-<platform>-<arch>/ convention; committed for macOS)
  test/verify.mjs       end-to-end verification script
.github/workflows/prebuilds.yml   5-platform prebuild CI
```

## Usage

```bash
npm install
node bin/scan_repo_map.mjs -d <target-dir> -n <module-name> -o <map.md>
node bin/scan_repo_map.mjs --merge a.md b.md -n all -o all.md
```

CLI flags are identical to the Bash version (-d/-o/-n/-x/-e/-m/--languages/--merge/-v/-h).

## Map sections and query patterns

| Section | Row shape | Answers | Query |
|---|---|---|---|
| Symbols | `📁 <relpath> [Lstart-Lend] <label> <name>` | Where is X defined | `grep 'class AuthRepository' map.md` → read `file:Lstart-Lend` |
| 🌐 Import graph | `📁 <file> imports(k): a, b…` | What a file depends on | `grep '^📁 <file>' map.md` |
| 🚪 File symbol index | `🚪 <file> exports(k): n1, n2…` | Which file has a symbol (incl. private) | `grep 'exports(.*<name>' map.md` |
| 🔗 Reverse references | `🔗 <module> (k importers): f1…` | Who is affected by changing it | `grep '^🔗 <module>' map.md` |
| 📡 API paths | `api-route` definitions / `api-call` sites | Cross-stack route pairing | grep the same path literal across stacks |

Empty sections are omitted. **Combined jump example** — "where does this page's data come from,
who is affected by changing a field":

1. `grep '<PageName>' map.md` → file and line range;
2. `grep '^📁 <that-file> imports'` → its providers/controllers;
3. `grep '^🔗 <controller/repository path>'` → all callers (blast radius);
4. Only then `read` the concrete files.

## Label glossary (symbol section)

`class/abstract-class/final-class/sealed-class/interface/enum/method/func/async-func`,
`provider/top-var/const`, `react-component/custom-hook/composable`,
`nest-controller/nest-service/typeorm-entity/room-entity/room-dao/hilt-module`,
`api-route/api-call/api-get/api-post/…`, `gin-handler/gin-middleware`,
`c-struct/cpp-class/cpp-func`, etc. When several labels hit one symbol, only the most specific survives.

## Known limitations

- **Vue (.vue) / Objective-C**: no tree-sitter grammar, not indexed (a .vue detection warning is emitted).
- **Dart api-call is a line-level heuristic**: calls spanning multiple lines and dynamically built URLs can be missed.
- **Heuristic labels** (api-route/api-call, zustand-store, …): a hit ≠ 100% semantics — always
  "locate via map, confirm in code".
- **Import normalization**: relative paths / Python dotted / Dart `package:self` resolve to
  repo-relative paths; TS aliases (`@/`, `~/`) are not resolved and aggregate as written.
- **🔗 external-dependency collapsing**: `dart:*`, non-self `package:`, provable JS bare package
  names collapse to `(N importers, external)`; to find library consumers grep 🌐 instead.
- **No semantic completeness**: the map holds no call graph or field read/write graph; never claim
  "all callers" from it.
- **--merge assumes one shared Source Path root**; merging maps from different roots warns.

## Tests and strip-compare

```bash
npm test        # fixture assertions + rule-manifest parity + gitignore parity
npm run golden  # strip-compare Node vs Bash on this repo and wisdom_app lib/ (normalized diff must be empty) + snapshot check
```

Language-pack availability baseline: every required kind is present in
@ast-grep/lang-{python,go,kotlin,java,swift,c,cpp} — no self-built packs needed (Dart uses this
repo's lang-dart).

Performance baseline (wisdom_app lib/, 106 Dart files): Bash ~5.1s, Node ~0.5s (each file parsed once).

## gitignore semantics (known behavior, identical to the Bash version)

- `.gitignore` applies only when the scan directory sits inside a git repo (itself or an ancestor
  has `.git`) — ast-grep → ignore crate's require_git default; when active, deeper .gitignore
  files override shallower ones.
- Character classes support negation `[!a]` (i.e. `[^a]`), ranges `[a-z]`; a `]` right after
  `[`/`[!` is a literal member; an unclosed `[` degrades to a literal; backslash escapes
  `\!`, `\#`, `\[` work.
- A directory hit prunes the whole subtree (negation cannot resurrect entries below an ignored
  directory, same as git).
- The Dart api-call line-level fallback follows symlinks when reading files (Bash parity: `find`
  without `-type f` + perl `open` follows symlinks): broken symlinks land in the ⚠️ diagnostics
  section. **Known behavior, identical across both versions — do not tighten one side only**
  (it would break the golden contract).

## Dart grammar source

The official `@ast-grep/lang-dart@0.0.7` grammar is too old to use. This pack's grammar source is:

- **nielsenko/tree-sitter-dart @ `b57d734c84f510bbd524097902cab671e4dbfca9`**

`src/` holds the committed C output of `tree-sitter generate` at that commit (CI builds from it
directly; no regeneration needed). To upgrade the grammar: clone that repo, check out the pinned
commit, `tree-sitter generate`, replace `src/`.

## Build

```bash
cd packages/lang-dart
npm install
npm run build          # tree-sitter build -o parser.so (tree-sitter-cli is in devDependencies)
```

Place the artifact at `prebuilds/prebuild-<platform>-<arch>/parser.so` (e.g. `prebuild-macOS-ARM64`);
`index.js` resolves it via `@ast-grep/setup-lang`'s `resolvePrebuild`, and postinstall falls back
to a local compile when no prebuild matches.

## CI (prebuilds)

`.github/workflows/prebuilds.yml`: triggered by `workflow_dispatch` and `push tag v*`. Matrix of
5 platforms: macos-13 (X64), macos-14 (ARM64), ubuntu-latest (Linux X64), ubuntu-24.04-arm
(Linux ARM64), windows-latest (Windows X64). Each runs `npm ci` then `tree-sitter build` from the
committed `src/`, uploading `prebuild-<platform>/parser.so`; the `merge` job bundles all five into
a complete `prebuilds/` artifact (`prebuilds-all`) for releases or manual pickup.

## Verify

```bash
cd packages/lang-dart
node test/verify.mjs /path/to/dart/sources
```

Registers this pack via `registerDynamicLanguage` (through prebuild resolution), parses every
`.dart` under the directory, and prints kind counts (class/enum/mixin/extension/extension_type/
top_level_variable/method/import), 3 pattern hit counts, and parse errors.

Current baseline (wisdom_app repo, read-only comparison):

- `lib/features/player` (9 files): class 29 / enum 1 / top-var 12 / method 110 / import 60 — matches the ast-grep CLI
- full `lib/` (106 files): parse errors = 0, kind counts identical to loading the grammar dart.so directly
